# Score Lyric Gloss

Add a readable meaning layer without changing the music or original lyric underlay.
Establish the source and target languages, selected parts/verses, and appearance.
If the score's lyric attachment is unreliable, correct or resolve it before
anchoring translations. Keep corrected original and annotated copies separate.
For installation, a human-operated walkthrough and a runnable synthetic example,
see [the user guide](README.md). The annotation script needs only Python's standard
library; translation is supplied by a person or agent, not generated by the script.

## Translation decisions

- Reconstruct complete words across syllables, melismas, ties and barlines.
  Do not translate each sung syllable independently or move the lyric itself.
- Preserve source word order. Use a short adjacent-word group for an idiom or
  reflexive/separable verb when strictly separate glosses would mislead. Record
  the exact source words covered; do not silently reorder an entire sentence.
- Keep articles, pronouns, negation and prepositions visible. Show contractions
  such as German `im` as `in the`; inflection need not become a grammar lecture.
  Prefer the contextual meaning over a dictionary's first sense. Brackets can
  distinguish an explanatory English addition not literally present in the source.
- The goal is comprehension, not rhyme, meter or singability. Preserve source
  spelling and document source typos separately. Look up genuinely uncertain
  historical/poetic usage; do not copy a copyrighted modern translation.
- Keep per-score language, translations, color and placement in job data, not
  shared defaults. Supply a compact parallel-text key when helpful for long spans.

## Encode and verify

Use editable MusicXML `direction/words` text at the first note of each source
word/group, not a fabricated second sung verse. The bundled
[gloss tool](scripts/gloss.py) inventories lyric words and adds checked mappings
without altering notes, durations, voices or lyrics. It currently requires one
selected monophonic lyric stream per invocation and contiguous full-word coverage.
For overlapping singers or verse mixtures, isolate streams explicitly or extend
the adapter; never merge them by XML document order.

```sh
python3 /path/to/skill/scripts/gloss.py inventory corrected.musicxml --part P1 --verse 1
python3 /path/to/skill/scripts/gloss.py apply corrected.musicxml gloss.json --out learning.musicxml
python3 /path/to/skill/scripts/gloss.py check learning.musicxml imported.musicxml
```

Mapping format: `part`, `verse`, `appearance` (`color`, `font_size`, `font_style`,
`placement`, `default_y`), and `units`: a list of `{ "source": "one word or adjacent words",
"text": "contextual gloss" }`. The tool consumes reconstructed source words in
order and refuses missing, extra or mismatching coverage. The source text is an
assertion, not a request to rewrite the source lyrics. Multiline gloss text may be used
when a short English phrase cannot fit horizontally.

Render in the target editor. Verify note/time/staff anchoring, original lyrics,
all gloss text and requested color—not just MusicXML validity. Inspect actual
readability at word starts, dense runs, melismas and system/page breaks. Text
directions may not reserve horizontal space automatically; adjust spacing,
line breaks or adjacent-word grouping without changing musical timing. A
text-preservation check does not certify translation quality or collision-free
engraving. Record those reviews separately. Do not weaken musical checks to
make annotations pass, and do not silently strip annotation styling on export.

The check command requires the original annotated MusicXML as its first input
(with generated `gloss-` IDs). It compares all text directions, including existing
expressive words, by part/bar/onset/staff, text, color and normal/italic style;
imported IDs may disappear. It rejects missing, duplicated or moved text. It does
not check font size, vertical spacing, translation quality or page layout.

MuseScore 4.7.4 preserved Apollo's 139 normal dark-blue directions at word starts.
Increasing lyric spacing in a per-job `.mss` style reduced collisions; automatic
placement sometimes staggered adjacent glosses vertically. Verify that staggering
still makes the source-word association clear. Color is a job preference, not a
requirement for other users or monochrome printing.
Check perceived contrast at the user's normal zoom, not just saved RGB values:
Luonnotar's dark blue survived import but its user initially mistook it for black.
Case and possessive endings may need multiword glosses attached to a single word;
keep such language-specific translations and uncertain poetic readings in job data.

When the input is a native file the user has edited by hand (Var det en dröm,
2026-10-17: an added pronunciation verse, courtesy accidentals), a MusicXML round
trip can discard those edits. Edit the native file's own text elements instead,
use `apply` on the editor's MusicXML export of that same input as the anchor
reference, and require the edited file's export to pass `check` against it. Also
diff the native files to show nothing else changed. Users may type a stray
syllable into the wrong verse; inspect its placement and style before deleting a
"translation" verse. Large lyric fonts (16 pt bold there) ran together at
MuseScore's 0.25 sp `lyricsMinDistance`. Raising it to 1 sp in that file's style
fixed this without timing changes. Some users want bare glosses only, with no
alternatives or notes in the score; keep explanations in the job notes.

Svarta rosor's first delivery (2026-10-23) kept a second (German) verse, so the
glosses formed a third line under the staff. The user then asked for it removed,
as for Var det en dröm, so offer that choice up front. In dense runs at
MuseScore's default 0.25 sp lyric spacing, the 9 pt glosses were wider than the
short sung words and stacked three deep into the piano's tuplet brackets and
notes. A per-job style with `lyricsMinDistance` 1.5 and `minVerticalDistance`
1.5 put each run on one line.
If `inventory` reports a broken word connection, check the source before
regrouping: there it exposed a transcription error, a held word encoded with a
hyphen.

## Carry learning forward

Keep the checked mapping, corrected-input hash, output paths, uncertainty and
review scope in the score record. After a demonstrated failure, add a focused
regression or lesson. Skill files preserve the workflow; they do not train a model.
